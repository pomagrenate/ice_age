# Code of Conduct

## Our Pledge

We want Iceage to be a welcoming, respectful, and constructive project for everyone who contributes.

Whether you are opening your first issue, submitting a pull request, improving the prompt, reporting a bug, or helping another contributor, we expect everyone to communicate with respect and focus on improving the project.

## Expected Behavior

Contributors are expected to:

* Be respectful and constructive.
* Assume good intentions.
* Give and receive technical feedback professionally.
* Focus criticism on ideas, code, behavior, and decisions — not people.
* Keep discussions relevant to the project.
* Accept different opinions and approaches.
* Help keep discussions clear, useful, and welcoming.
* Take responsibility for mistakes and learn from them.

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment, discrimination, or personal attacks.
* Trolling, insults, or deliberately hostile behavior.
* Unwelcome sexual or personal attention.
* Publishing someone's private information without permission.
* Threats or intimidation.
* Deliberately disrupting discussions or contributions.
* Repeatedly ignoring reasonable requests from maintainers.
* Any other behavior that would reasonably make the project unsafe or hostile for others.

## Technical Discussions

Iceage is an engineering project. Strong technical disagreement is welcome.

You can challenge:

* A design decision
* A prompt change
* An implementation
* A benchmark result
* A proposed feature
* A maintainer decision

Do it with evidence and reasoning.

A disagreement should look like:

> "This change increases verbosity in security-related responses. Here is an example and a possible alternative."

Not:

> "This is a stupid change."

**Attack the problem, not the person.**

## Pull Requests and Issues

Keep issues and pull requests focused.

When submitting a contribution:

* Explain what changed.
* Explain why it changed.
* Provide examples when behavior changes.
* Keep discussions relevant to the proposed change.
* Respond to technical feedback constructively.

Maintainers may close discussions or reject contributions that are outside the project's scope. Disagreement is fine; disrespect is not.

## Enforcement

Project maintainers are responsible for clarifying and enforcing this Code of Conduct.

They may take appropriate action in response to unacceptable behavior, including:

* Asking someone to stop a behavior.
* Removing or editing inappropriate comments.
* Closing issues or discussions.
* Rejecting or closing pull requests.
* Temporarily or permanently restricting participation.

Actions will be based on the behavior and its impact on the project community.

## Reporting

If you experience or witness unacceptable behavior, please report it privately to the project maintainers rather than escalating the situation publicly.

When reporting an incident, include:

* What happened
* When it happened
* Where it happened
* Who was involved, if known
* Any relevant links, screenshots, or context

Reports will be handled as confidentially as reasonably possible.

## Scope

This Code of Conduct applies to project spaces, including:

* GitHub issues
* Pull requests
* Discussions
* Code reviews
* Project-related communication
* Other spaces where someone is representing the Iceage project

## In Short

Iceage values simple, focused, technical collaboration.

Be direct.

Be respectful.

Challenge ideas, not people.

Keep the project useful.

> **Less drama. More signal. 🦣**
